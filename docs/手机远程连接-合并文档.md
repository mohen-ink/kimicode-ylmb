## 3. 集成顺序

1. **基线确认**：确认当前提交与基线一致。
2. **许可证与属性**：二维码库及其许可证、连接器许可证文本，以及 `.gitattributes` 中的 `-text` 行（否则固定摘要会被检出时改写）。
3. **隧道组件**：`scripts/mobile_tunnel.py`（可独立测试：包内许可证校验、下载重试、运行目录校验）。
4. **桥**：`scripts/mobile_bridge.py`（依赖标准库与隧道组件的运行时合同）。
5. **worker**：`scripts/mobile_worker.py`（依赖桥的管理器；后台侧客户端与 worker 进程在同一文件）。
6. **用量服务集成**：`scripts/service.py`（前置分流、惰性客户端、注入链、退出时只 detach）。
7. **前端资产**：二维码库 → 二维码桥接 → 旧通道适配 → 手机控制面适配 → 手机浮层 → 浮层样式（顺序必须与用量服务中的资源清单一致；用量面板脚本始终最后）。
8. **清单与命令文档**：`kimi.plugin.json`、`commands/update.md`。
9. **文档**：`README.md`、`CHANGELOG.md`、`HANDOFF.md`、`docs/`。
10. **验收**：Python 3.8 语法检查、各脚本的 `node --check`、清单 JSON 解析、固定摘要复验、隔离回归；公网与真机验收另行进行（见[手机远程连接-最终工作文档-20261007.md](手机远程连接-最终工作文档-20261007.md) §7）。

## 4. 生命周期

### 4.1 进程与组件

- **用量服务**：由会话钩子按心跳拉起（`bootstrap.cmd` → `service.py --tick`）。`/plugins reload`、新会话与钩子心跳**不会**替换运行中服务的代码——改动 Python 代码后必须显式重启（在**实际安装目录**执行；从另一份源码副本重启会被所有权检查拒绝）。
- **mobile worker**：首次需要手机控制面时由后台惰性拉起为独立子进程。后台退出或重启只 detach，不停止桥会话、隧道与配对；同版本新后台经状态记录、进程身份与认证信息三重核实后重连接管。
- **显式停止**：浮层「停止」撤销配对、会话、WebSocket 与隧道，worker 自行退出并清理记录与锁。
- **连接器**：运行目录位于插件树外，插件更新不覆盖；每次启动前复验固定大小与摘要。

### 4.2 版本升级与迁移

- worker 记录中的版本与协议号必须与当前版本一致才会被接管；任何环节核实失败一律拒绝。
- **旧版本 worker 仍在运行时不接管、不擅自结束**：经同等强度的核实后，只读取其真实状态（不伪装成已关闭，使「停止」按钮可用）并放行显式停止。迁移路径是浮层点「停止」后再升级，**不是**手动杀进程或重启电脑。
- **进程隔离**：worker 不把自身加入任何 Windows Job；后台侧只做只读探测，不能确认不在 Job 中时就带脱离标志启动，失败即拒绝，绝不静默继承后台的 Job。
- **存活凭证是真实操作系统锁文件**：进程退出或崩溃时由系统自动释放；锁文件可能在磁盘残留（无害空文件），活性以「能否取得锁」判定，不凭文件是否存在判断。
- **状态目录**：位于 `KIMI_HOME/usage-dashboard/runtime/mobile-worker/`，无跨版本结构迁移——记录结构校验不通过即视为不可用并重新拉起；进程号复用以创建时刻比对拒绝。
- **权限收紧**：状态目录与凭据文件在创建时收紧权限（Windows 使用受保护的最小授权 DACL 并关闭继承，其他平台使用受限权限位）；任何一步失败即拒绝服务，绝不静默以宽权限继续。

### 4.3 手机只读用量与聊天桥解耦

只读用量是 worker 内的独立通路：仅对已配对设备放行，后端只从**固定本机用量服务**读取既定只读数据的白名单字段，不接受手机传入任意地址。取数有界（单次超时、总截止、短时新鲜缓存、失败时有限降级旧缓存），失败一律返回受控错误。

**本机用量服务停止只让手机用量页不可用，不影响已开启的聊天桥**；反之停止聊天桥也不会重启用量服务。两者只共享 worker 进程与配对会话。

## 5. 源码与安装目录（部署边界）

- **源码**：仓库工作区。改动不影响正在运行的服务。
- **安装目录**：托管安装位置，用量服务从这里加载代码。
- **部署方式**：把源码中的同名文件复制到安装目录，再在实际安装目录执行 `python scripts/service.py --restart`。仅改文档或样式不需要重启；改任何 Python 文件或注入资产必须重启才生效。
- **桌面注入资产**由用量服务启动后按摘要自动同步，不手工复制。
- **组件运行目录**位于插件树外，升级插件不覆盖。

### 部署与重载边界

| 操作 | 对用量服务 | 对手机连接（worker） |
|---|---|---|
| 插件重载、新会话、钩子心跳 | 不替换已加载代码 | 无影响 |
| 仅改文档 | 无需重启 | 无影响 |
| 改前端注入资产 | 运行中按摘要自愈同步到桌面资源目录 | 无影响 |
| 改 Python 文件（含桥、隧道、worker、用量服务） | 必须显式重启 | **重启后台不中断**已开启的手机连接（worker 独立存活、同版本接管）；但若桥本身变更，须先「停止」手机连接让旧 worker 退出，再开启以使用新代码 |
| 显式「停止」手机连接 | 无影响 | 撤销全部配对、会话、WebSocket 与隧道，worker 退出 |

## 6. 回滚（保留用户数据）

回滚只回退**插件文件**，不动用户数据：

- **保留**：用量采集状态文件、价格配置、忽略项记录、桌面路径记录、`KIMI_HOME/usage-dashboard/runtime/`（组件与 worker 状态目录）、桌面配置及其时间戳备份。
- **步骤**：
  1. 若手机连接已开启，先在浮层点「停止」（撤销配对与隧道，worker 退出）。
  2. 用目标版本的同名文件覆盖安装目录（或重新安装目标目录）。
  3. 在实际安装目录执行 `python scripts/service.py --restart`。
  4. 验证：`curl --noproxy '*' -s http://127.0.0.1:39281/api/status` 返回预期版本。
  5. 需要手机连接时重新开启并重新扫码（旧隧道地址与配对会话随停止失效，属设计语义，不是数据丢失）。
- **更新器自保护**：本地预览形态下更新器拒绝执行且不改动任何文件（缺少核心运行文件、或移动端运行时只给一半时同样拒绝写入并返回独立退出码）；预览形态的在线更新接口也一律拒绝。即使手工运行更新器，也不会覆盖预览文件。

## 7. 合并红线

- 不宣称公网端到端、真机扫码、真实桌面界面交互、公网上传链路、真实隧道生命周期或真实桌面生命周期接管已经验收。
- 测试计数必须与机器证据一致，不夸大：隔离回归计数是执行计数，不能相加当作项目测试总数，也不代表全项目去重测试全绿。
- 发布隔离回归迁移后 54 个检查项通过；计数含跳过与继承重复，须按最终工作文档说明使用，不将隔离通过表述成公网真机验收通过。
- 状态接口返回正常不替代真机与公网验收。
- 手机远程连接为预览功能，接口与行为可能继续调整。

## 8. v3.4.0 合并增量（2026-10-09）

§1–§7 是 v3.3.3 合并的原始记录。本节只记 v3.4.0 相对它的增量。

### 8.1 合并方向与基底

以「自建 Python 中继」分支（本机形态 `3.3.7-local`，分支 `feat/mode-slider`）为**基底**，把主线的安全加固反向移植进来。两棵树无共同祖先，故未用 `git merge`，而是**整体替换差异文件 + 定向移植**，落在分支 `feat/merge-relay-v3.4.0`。

### 8.2 中继方案替换（frp → 自建 Python 中继）

| | 旧（frp） | 新（自建 Python 中继） |
|---|---|---|
| worker 侧 | `RelayRuntime` 下载并托管 `frpc.exe` | `RelayClient` 纯标准库 WS 客户端 |
| 传输 | frp TCP + TLS + CA 固定 | 明文 `ws://` / `http://` |
| 配置 | 每次 `/start` 由客户端传入并严格校验 | 服务端 `relay.json` 持久化 + `GET/POST /api/mobile/relay/config` |
| 二进制 | 需下载 frpc 并做 SHA-256 完整性校验 | 无二进制，`relay_server.py` 随源码分发 |
| 重连 | 依赖 frpc 自身 | 指数退避 + `X-Relay-Resume` 续期，配对地址存活 |

变更文件：`scripts/mobile_relay.py`（整模块替换）、`scripts/mobile_bridge.py`、`scripts/mobile_worker.py`、`scripts/service.py`、`assets/kimi-mobile-api.js`、`assets/kimi-remote-widget.js`。新增 `scripts/relay_server.py`、`scripts/relay_config.py`。移除 `deploy/frp/` 与 `assets/vendor/frp-0.67.0-LICENSE`。

### 8.3 从主线反向移植的加固

1. **`server.token` 自助补建**：新增 `scripts/mobile_credentials.py` 与 `scripts/mobile_security.py`；桥在首次显式开启时补建缺失 token（原子、不覆盖、受保护 DACL），并以新错误码 `SERVER_TOKEN_UNAVAILABLE` 回报失败。
2. **手机端会话归档 / 删除 / 导出**：`POST /api/v1/sessions/{id}:archive|:delete|/restore`、`/export` 与 `POST /api/v2/sessions:archive|:restore` 放行，均为精确路径 + POST，不做前缀匹配。

### 8.4 基底自带、随本次一并启用的修复

- WS 心跳桥接（`client_hello` + `ping→pong`），修掉手机聊天 WS 约 20 秒被踢。
- `OWNER_LOST_GRACE = 3`：连续 3 次复核失败才撤销连接。
- 模式滑杆（`modes.json` + `GET /api/modes` + 四个 POST）。

### 8.5 未移植（本次明确取舍）

- **owner 身份二次证明**（`_verify_owner_auth` / `_owner_matches` 三次复检）：保留基底的 pid + 端口 + healthz 判定。
- **控制面 JSON 重复键拒绝**（`_json_no_dup_object`）：保留基底的 `json.loads`。
- **中继模式拒绝伪造转发头**：保留基底行为（信任 `CF-Connecting-IP`）。
- **`tests/` 目录**：按决策整体移除，v3.4.0 起仓库不再附自动化测试。

### 8.6 更新器清单调整

`scripts/updater.py` 的成组交付清单按合并后文件集重算：`MOBILE_RUNTIME_GROUP` 加入 `scripts/relay_config.py`（`service.py` 顶层 import）与 `scripts/relay_server.py`，移除 frp 许可证；`LOCAL_ONLY_KEEP` 含 `mobile_relay.py` / `mobile_credentials.py` / `mobile_security.py` / `relay_config.py`。**新包必须包含上述四个文件**；其中 `relay_config.py` 额外受 `LOCAL_ONLY_KEEP` 保护——因为它被 `service.py` 顶层导入，若包完全不含手机运行时（完整性闸门的 partial 检查为空、放行），同步删除会把它清掉而导致用量服务无法启动。

### 8.7 红线（在 §7 基础上追加）

- 自建中继**明文传输**，且 token 不内置仓库、只存于部署环境与本机 `relay.json`，是已知并接受的风险，不得表述为"加密"或"端到端安全"。
- v3.4.0 移除 `tests/` 后，**不得引用 3.3.x 的测试计数**当作 v3.4.0 的覆盖证据；本次仅完成编译、导入链与白名单行为验证。
- 自建中继在真实 VPS 上的部署与实体手机蜂窝网链路仍未验收。
