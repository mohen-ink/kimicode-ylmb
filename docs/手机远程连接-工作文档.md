> 适用范围：Kimi Code 用量面板（插件 `kimi-code-usage`）的**手机远程连接**子功能。

## 1. 目标与形态

**目标**：手机浏览器远程使用当前电脑 Kimi Code Agent 会话——看流式回复、发 prompt、审批、回答提问、上传文件；配对是会话控制授权，不是普通只读网页。

| 模式 | 连接路径 / 手机地址 | 使用条件 |
|---|---|---|
| 内网 `lan` | 手机 → 电脑，`http://<RFC1918 IP>:<端口>` | 同一可信 Wi-Fi；明文 HTTP；无需连接器 |
| CF 隧道 `internet` | 手机 → Cloudflare → cloudflared → 桥，临时 HTTPS | 固定 CF 组件；Cloudflare 终止 TLS，可见会话内容 |
| 中继服务器 `relay` | 手机 → 用户 frps → frpc → 桥，`http://<公网IPv4>:<remote_port>` | 用户已有服务器并自行部署 frps；第一阶段仅明文公网临时联调 |

- v3.3.3「只提供外网」是历史口径；当前浮层有三模式，运行中先停止才能切换。打开浮层、读状态或选模式均不安装/开启，关闭状态只保存模式偏好 `kur-mode`。
- 官方中继仍运行时只提供提示与「停止官方中继」，不自动停止或代为切换；内网不是旧版通道。
- 手机使用 **Kimi 原生手机 SPA**，桥处理配对和受限 HTTP/WebSocket 转发，不维护第二套应用。已配对设备可查看同源只读用量页。
- 桥运行于**独立 detached worker**；daemon 退出/重启只 detach，现有连接、配对与会话留在 worker 中。worker 自身安全脱离 daemon Job，frpc 客户端由 **worker 自有 Job** 管理。

**安全边界与不承诺**：

- relay 的**电脑 frpc → 服务器 frps 强制 TLS**，使用用户自建 CA 的**公开证书**验证，服务器证书含公网 IPv4 的 **IP SAN**，并用 token 认证；不允许跳过校验。relay 桥只 bind `127.0.0.1`，frpc 指向实际分配的桥端口。
- relay 的**手机 → 服务器是明文 HTTP**：配对兑换、会话 Cookie、消息与文件可被窃听篡改。只有用户明确同意才用于临时联调；**不等于安全公网或 E2EE**。第一阶段不需要域名、Nginx 或手机 HTTPS。
- CF 同样不是端到端加密，Cloudflare 可见 TLS 终止后的内容；内网仅用于可信 Wi-Fi。三种模式均非 P2P。
- CF 临时地址停止/重开会变化、无 SLA；relay IP/端口可由用户固定，但这不保证服务可用或永久 URL。relay 断线撤销全部授权，必须显式重开并重新配对。

## 3. 整体结构

```text
桌面「手机」浮层 → loopback 控制头 → service.py:39281
  └─ /api/mobile/* → IPC secret → mobile_worker.py（独立 detached）
       ├─ mobile_bridge.py   配对 / SID / 受限 HTTP + WS / owner 复核
       ├─ mobile_usage.py    同源只读用量（固定 loopback 白名单）
       ├─ lan               RFC1918 监听 → 可信 Wi-Fi 手机 HTTP
       ├─ mobile_tunnel.py  cloudflared → Cloudflare → 手机 HTTPS
       └─ mobile_relay.py   frpc → TLS + CA/IP SAN + token → 用户 frps
                                                        └─ 手机 HTTP
relay：frpc 转发 127.0.0.1:<实际桥端口>，不将桥 bind 到公网网卡
```

| 层 | 文件 | 职责 |
|---|---|---|
| 浮层 | `assets/kimi-remote-widget.js` | 三模式、风险/下载同意、relay 配置密码框、安装/启停、离线 QR、换码、状态轮询 |
| 控制面 | `assets/kimi-mobile-api.js` | 固定 loopback、自定义控制头、拒绝重定向、有界超时；relay token 只在受守卫的开启请求体传给 worker，不持久保存 |
| 旧通道探测 | `assets/kimi-remote-api.js` | 官方中继探测及显式停止 |
| 二维码 | `assets/kimi-remote-qr.js` + `assets/vendor/qrcodegen.js` | 离线 QR，失败可复制链接 |
| 样式 | `assets/kimi-remote-widget-live.css` | 样式更新不等于通用 JS 热重载 |
| 用量服务 | `scripts/service.py` | 采集/注入，mobile 前置分流，异常拒绝且不回退旧接口；退出只 detach |
| worker | `scripts/mobile_worker.py` | IPC、进程隔离、状态记录/认证接管、客户端 Job 与权限收紧 |
| 桥 | `scripts/mobile_bridge.py` | 配对/SID、精确 HTTP/WS 白名单、owner 复核、限流、模式生命周期 |
| 只读用量 | `scripts/mobile_usage.py` | 固定 `127.0.0.1:39281` 白名单字段，只给已配对设备 |
| CF 组件 | `scripts/mobile_tunnel.py` | CF 固定安装/校验、启动/停止 |
| frp 组件 | `scripts/mobile_relay.py` | 固定 ZIP/EXE/许可证校验、强制 TLS、临时 ACL 配置、frpc 回收 |
| 服务端模板 | `deploy/frp/frps.toml.example` | 用户自行部署 frps；限制 allowed ports，不公开管理面板 |

### 桌面接缝

- **注入顺序**：用量服务把固定顺序的资源同步到桌面资源目录并按摘要注入页面：二维码库 → 二维码桥接 → 旧通道适配 → 手机控制面适配 → 手机浮层；用量面板脚本始终最后。同步不完整的文件不注入，并会自动清理旧标签。
- **入口**：侧栏头部与最小化栏各有「手机」按钮，仅存在于桌面注入链内。
- **钩子**：清单的 4 个会话钩子统一走 `scripts/bootstrap.cmd`，只负责拉起与心跳用量服务，**不会自动开启手机连接**。

## 4. 配对与安全模型

### 4.1 配对

- 链接使用对应模式 origin 加 `/mobile/pair#pair=<一次性配对码>`：CF 为 HTTPS 随机域名，lan 为 HTTP 内网 IP，relay 为 `http://<公网IPv4>:<remote_port>`。fragment 不随首次 HTTP 请求发送，但兑换会同源提交；**不能把 fragment 当加密或不留浏览器历史的保证**，不要分享完整链接。
- 配对码**10 分钟有效、一次性**，兑换一台设备即销毁。同一二维码不能连多台；「生成新二维码」作废旧未用码，已连设备不受影响。
- 会话 Cookie 为 **HttpOnly、SameSite=Strict**；只有 CF HTTPS 使用 Secure，lan/relay HTTP 不能声称有 Secure 传输保护。兑换有限速；已配会话再进入配对页直接进入应用，不消耗新码。

### 4.2 设备会话生命周期

- 最多 8 台设备；闲置 24 小时滑动过期、绝对寿命 7 天，只有真实认证活动续期且不越过绝对上限。到期会切断 WS。
- **停止即全部撤销**：配对码、SID、缓存、WS、桥监听与连接器一并回收，worker 退出并清理状态/锁。relay 的 ACL 临时配置含秘密，停止时删除。
- **relay 断线即撤销**，不让 frpc 重连恢复旧授权；必须用户显式重开，再让手机重新配对。daemon detach 与断线不同：detach 不停止仍健康的 worker/连接。

### 4.3 桌面实例复核

- 开启前核实桌面注册地址/端口、进程身份与创建时刻、端口 owner、健康状态，防 PID 复用或连接到其他实例。
- 运行中每 2 秒复核，任一失败停止，不自动切到其他实例。身份检查偏严，短暂失败可能撤销；真实生命周期仍待验收。

### 4.4 凭据与数据边界

- **桌面 `server.token` 不出桥**：仅用于上游授权，不进入 URL、Cookie、二维码、日志或响应；手机只有无权限占位值。
- **frp token 是另一份秘密**：仅在密码框输入，受守卫的开启请求传入 worker 内存与 ACL 收紧的临时配置；不进 URL、argv、日志、status 或 localStorage，不在 daemon 状态文件保存。停止删除临时配置；别在聊天、截图或命令行贴真实 token。
- `ca_cert` 仅是用户自建 CA 的**公开 PEM 证书**，可粘贴；CA 私钥与服务器私钥仅留服务器，绝不交给插件/手机。服务器 token 放权限受限的服务端配置，不能用聊天传递。
- 响应体/头/WS 消息进行桌面凭据泄露检查，命中返回通用错误；有限错误码不回传原始日志、runtime 路径或秘密链接。这不能抵消 relay 手机 HTTP 被监听或篡改的风险。
- 匿名与已认证请求分桶限流，命中返回 `Retry-After`。

### 4.5 放行面（白名单）

手机侧请求实行**精确方法与路由白名单**，机器级与越权面默认拒绝：

- **只读面**：健康检查、元信息、模型、工作区、技能、工具、能力、搜索、媒体、认证、配置（原生已脱敏）以及会话列表。
- **会话读段**：会话下的已知只读子资源（消息、审批、提问、任务、文件历史、快照、状态等）。
- **会话写**：发消息/中止/引导、审批、回答问题、生成标题、任务取消或分离、文件系统只读动作，以及会话级的分叉、压缩、撤销、恢复、**归档、删除、导出**；批量归档/恢复走 v2 精确动作（`POST /api/v2/sessions:archive` 与 `:restore`）。归档/删除/导出**仅接受 POST**，GET 一律拒绝。
- **全局配置写**：仅开放窄白名单键——默认模型、思考选项、自动会话标题、默认计划模式；空对象、未知键、重复键、危险键一律拒绝。
- **文件**：上传与下载。上传请求体上限 32 MiB（含包装开销）；仅精确上传路径的接收预算放宽为闲置 120 秒、累计最长 600 秒，其它路径保持较短预算。
- **静态面**：首页、索引页、站点图标、形状校验过的资源路径、会话管理页，以及单段的会话与设备路径；其余静态路径不转发。
- **一律拒绝**：终端、调试、关机、远程控制、权限、供应商、插件、MCP、OAuth、连接、运行时、机器级文件系统操作，以及原生未知子资源。
- **WebSocket**：只向上游注入真实凭据，客户端仅回显占位子协议；消息按类型白名单过滤，终端类消息一律断开；同时连接数有界。

### 4.6 授权语义

扫码或打开配对链接即授予手机对当前电脑 Agent 的**会话面控制权限**：查看会话、发 prompt、审批、回答提问、上传与下载文件。手机不能直连终端或机器级管理接口，但**这不消除控制电脑的风险**——请勿把配对链接或二维码交给他人。

## 5. 使用流程

### 5.1 三模式开启与配对

1. 安装并启用插件，打开「手机」。已有连接时先显式停止，再选模式；不自动迁移正在运行的 worker。
2. 按所选模式准备：
   - **内网**：选择本机 RFC1918 网卡，确认明文 HTTP 仅可信 Wi-Fi 后开启。监听端口从 `39282` 起取空闲，手机须连同一可信 Wi-Fi，不安装组件。
   - **CF 隧道**：电脑可访问 GitHub 官方发布与 Cloudflare；勾选下载同意安装 cloudflared，再单独勾选第三方中继同意并开启。首次可能 2–3 分钟，勿重复点击；安装成功不等于开启。出站须允许 `7844/UDP`（QUIC）或 `7844/TCP`，无永久地址/SLA，不支持 SSE（用 WS）。
   - **中继服务器**：先完成 §5.2。勾选下载同意安装固定 frp 客户端；填 `server_ip`（公网 IPv4）、`server_port`（示例 7000）、`remote_port`（示例 6000）、密码框 `token` 与公开 PEM `ca_cert`。单独同意公网明文 HTTP 的临时联调风险后开启；不需要域名或 Nginx。
3. 就绪且配对码有效才显示二维码/链接。手机用**系统浏览器**扫码或打开；relay 为 `http://IP:remote_port/mobile/pair#pair=…`。不要分享链接；手机浏览器若强制 HTTPS，不把 HTTP 第一阶段冒充 HTTPS 部署。
4. 第二台手机点「生成新二维码」，旧码作废，已连设备不受影响。
5. 点「停止」撤销全部授权和连接器；relay 删除临时配置。断线后必须显式重开并重新扫码，不自动恢复旧会话。

电脑持续开机且桌面 owner 可用；关闭浮层不停止连接。daemon detach/restart 不停止健康 worker。用量服务停止只使手机只读用量页不可用。插件不自动改防火墙、不部署服务器、不需电脑路由器入站端口映射。

### 5.2 服务器准备与 frps 部署（用户自行执行）

**以下都是用户后续部署动作，不是本轮已执行的命令或验证记录。** 用户已有服务器，但服务器 OS/架构、目录与防火墙环境尚未确认；下面 Bash/POSIX 示例只适用于具备这些工具的服务器，不默认用户服务器是 Linux。Windows 服务器应下载对应 Windows 包、预先收紧目录 ACL，并使用绝对配置/证书路径；不能直接照搬 `umask/chmod` 当作 Windows 权限设置。

#### A. 选择同版本官方 frps

1. 查看客户端代码 `scripts/mobile_relay.py` 中的 `RELAY_VERSION`，到 [frp 官方 releases](https://github.com/fatedier/frp/releases) 选择**相同版本**、适合服务器 OS/CPU 的发布包，按该发布的校验材料核对后解压。不要猜版本或随意用 latest；客户端的 Windows ZIP/EXE 摘要不能用于服务器其他架构包。
2. 准备独立私有工作目录，frps 二进制与配置由部署用户管理。服务配置模板为 [`deploy/frp/frps.toml.example`](../deploy/frp/frps.toml.example)，它不是插件自动部署指令。客户端 frpc 由面板安装，不需要手动启动第二份客户端。

#### B. 先建私有目录，再自建 CA 和 IP SAN 证书

在服务器具备 Bash 与 OpenSSL 时，可使用下列最少命令。工作目录应为新建私有目录；若目录已存在，应先人工确认所有者与权限。输入真实公网 IPv4（公开信息，不是 token）；CA/key 只在服务器生成。**必须先 `umask 077` 与私有目录，再生成私钥**：

```bash
(
set -e
umask 077
mkdir -m 700 "$HOME/kimi-frps-private"
cd "$HOME/kimi-frps-private"
read -r -p '服务器公网 IPv4: ' SERVER_IP
openssl req -x509 -newkey rsa:3072 -sha256 -nodes -days 365 \
  -keyout ca.key -out ca.pem -subj '/CN=Kimi frp private CA' \
  -addext 'basicConstraints=critical,CA:TRUE' \
  -addext 'keyUsage=critical,keyCertSign,cRLSign'
openssl req -new -newkey rsa:3072 -sha256 -nodes \
  -keyout server.key -out server.csr -subj "/CN=$SERVER_IP"
cat > server.ext <<EOF
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
subjectAltName=IP:$SERVER_IP
EOF
openssl x509 -req -in server.csr -CA ca.pem -CAkey ca.key -CAcreateserial \
  -out server.pem -days 365 -sha256 -extfile server.ext
chmod 600 ca.key ca.pem ca.srl server.key server.pem server.csr server.ext
)
```

- 这是含 **IP SAN** 的服务端证书，不是只填 CN 的自签证书。证书公网 IP 必须等于面板 `server_ip`；IP 改变或证书到期要重新签发并更新部署。
- `ca.pem` 是**公开 CA 证书**，仅它可交给面板；`ca.key` 与 `server.key` 绝不离开服务器。`-nodes` 生成无口令私钥以便服务读取，必须依赖私有目录和 `600` 权限保护。Windows 用只允许部署/服务账号读取的等效 ACL。
- 命令需要支持 `-addext` 的 OpenSSL。若服务器版本不支持，先准备支持该选项的工具，或用经确认的等效证书配置；不要取消 CA/IP SAN 校验。

#### C. 使用模板配置，不在命令参数/聊天暴露 token

1. 将模板复制为私有目录里的 `frps.toml`，用本地编辑器替换占位符；例如 POSIX 环境可执行（模板来源换成服务器实际绝对路径）：

   ```bash
   cp /absolute/path/to/frps.toml.example "$HOME/kimi-frps-private/frps.toml"
   chmod 600 "$HOME/kimi-frps-private/frps.toml"
   ```

2. 保持模板 **token 认证**与**强制 TLS**设置，证书路径指向本目录 `server.pem` / `server.key`，建议填写真实绝对路径。`bindPort` 示例为 `7000`，`allowPorts` 仅允许访问端口 `6000`（用户改端口时同步修改允许范围）；**不要开放任意代理端口，不启用/公开管理面板或 dashboard**。
3. 将模板 token 占位值替换为本地密码管理器生成的强随机秘密；客户端密码框填写同一份 token。占位值不是可用密码；不要把真实 token 写进命令参数、聊天、截图、URL 或示例，也不要通过会记录内容的管道/log 输出它。配置只允许部署/服务账号读取，并注意编辑器备份也要私有。
4. 本文选择「编辑模板」而非 shell 拼接秘密 TOML。若自行脚本化，必须先收紧权限，使用隐藏输入（Bash `read -r -s`）且避免 shell 历史记录、终端回显、`set -x` 与输出 token；不要将 token 字面值写在 shell 命令中。未确认固定版本支持前，**不使用臆测的 `tokenSource` 配置**。

#### D. 手动开放端口并前台启动

- 用户在云安全组与服务器防火墙**手动**允许控制端口 TCP `7000`、访问端口 TCP `6000`。控制端口只允许电脑实际出口 IP；访问端口尽量只允许本次手机测试出口 IP/网段，不默认 `0.0.0.0/0`。蜂窝出口可能变化/共享，须人工确认来源规则；不要为联调顺手公开管理面板或额外端口。
- 在私有目录放入所选发布包的 frps 后，用户先前台执行，便于看到服务是否就绪：

  ```bash
  ./frps -c frps.toml
  ```

  若不在配置所在目录，请用实际绝对路径，如 `./frps -c /actual/private/path/frps.toml`。Windows PowerShell 可适配为 `& 'C:\actual\frp\frps.exe' -c 'C:\actual\private\frps.toml'`，模板证书路径也用绝对路径；这是路径示例，不表示该目录已存在。不要在参数添加 token。
- 后台服务/自动启动方式需按实际 OS 另行配置，不假设已具备 systemd，也不在本轮远程操作用户服务器。联调结束停止面板 relay 与服务器 frps，关闭临时安全组/防火墙规则；固定 IP/端口仍须重新配对，旧授权不得恢复。

### 5.3 控制面 API 与状态兼容

所有 `/api/mobile/*` 在 loopback 由 service 分流到 worker，POST 需 `X-Kimi-Mobile-Control: 1`，bridge 负责 Host/Origin/CORS/请求体守卫。以下为字段合同，不是包含真实 token 的可执行命令：

| 接口 | 请求对象 |
|---|---|
| `GET /api/mobile/status` | 只读，不安装/开启 |
| `POST /api/mobile/connector/install` 默认 CF | `{consent:true, consent_version:"cloudflare-quick-2026-09-v1"}`；旧参数不变 |
| 同接口 relay 安装 | `{mode:"relay", consent:true, consent_version:"frp-tcp-http-v1"}` |
| `POST /api/mobile/start` CF | `{owner_origin, mode:"internet", relay_consent:true, consent_version:"cloudflare-quick-2026-09-v1"}` |
| 同接口 relay 开启 | `{owner_origin, mode:"relay", relay_consent:true, consent_version:"frp-tcp-http-v1", relay_config:{server_ip, server_port, remote_port, token, ca_cert}}` |
| `POST /api/mobile/pair/rotate` | `{}`；旧未用码撤销 |
| `POST /api/mobile/stop` | `{}`；幂等全撤销 |

- `state` 保持 `off|starting|on|stopping`。旧 `connector` **始终是 CF**，新增 `relay_connector` 为 frp，组件状态为 `missing|installing|installed|failed`；CF 版本仍 `2026.9.3`，frp 为 `RELAY_VERSION`。
- `tunnel` 是当前模式通用连接状态（`off|starting|ready|failed`）；relay 就绪返回 `public_origin=http://IP:remote_port`，不将它当 HTTPS。有效配对才有 `url/expires_at`；`pair_state` 若出现仅 `missing|available|used|expired`。
- `relay_config` 只用于本次开启，特别是 token 不进入返回 status、磁盘状态记录、日志或 localStorage。CA 只接收公开证书。
- 旧版本 worker 提供经认证的实际状态与显式 stop，附迁移提示，不假装 off、不擅杀。daemon 同版本接管核实记录+进程身份+认证 meta；异常 fail closed，不回退 legacy、不自动启动。

## 6. 排障速查

| 现象 | 处理 |
|---|---|
| 安装不可点 | 检查下载同意、已有连接与安装中状态；先显式停止，不重复点击 |
| 安装/摘要失败 | 检查官方发布站点可达、包内 LICENSE 与固定 runtime 完整性；显式重试，不绕过 TLS 或校验 |
| 平台不支持 | 插件连接器为 Windows AMD64；服务器包另外按实际 OS/CPU 选择 |
| CF 启动失败/超时/退出 | 检查 Cloudflare 出站 `7844/UDP` 或 `7844/TCP`，无需电脑入站映射 |
| relay 控制连接失败 | 检查公网 IPv4、控制端口、frps 前台状态、安全组与服务器防火墙来源限制、同版本与 token 一致；脱敏排查，不粘贴 token |
| relay TLS/证书失败 | 核对公开 CA PEM、IP SAN 与 `server_ip`、有效期和服务器证书路径；不关闭 TLS，不启用跳过证书验证 |
| relay 注册端口失败 | 访问端口是否被占用、是否在 frps `allowPorts` 内；`remote_port` 与控制端口是不同用途 |
| relay 就绪但手机访问失败 | 检查访问端口来源规则与蜂窝出口变化、手机是否误用 HTTPS、frps/frpc 是否仍连接；TLS 控制段就绪不证明手机链路验收 |
| relay 断线/旧 Cookie 失效 | 授权已撤销，必须显式重开并新码配对，不能自动恢复 |
| 二维码/配对失败 | 用系统浏览器打开复制链接；配对码 10 分钟一次性，过期/已用须换码 |
| 会话到期/限流/拒绝 | 24h idle/7d 绝对寿命后重新配对；限流等 `Retry-After`；白名单外操作按设计拒绝 |
| owner 失联或旧 worker 提示 | 桌面恢复后显式重开；旧 worker 点「停止」后升级，不杀无关进程、不靠重启电脑清场 |
| 大图/文件上传失败 | 上限 32 MiB 含包装，idle 120s/累计 600s；检查蜂窝上行，公网未验收 |
| 用量面板离线 | 用户在实际安装目录重启用量服务，不把源码副本当安装目录 |
