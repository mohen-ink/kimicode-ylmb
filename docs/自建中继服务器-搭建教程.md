# 自建中继服务器 · 搭建教程

自建中继使用**一个端口**提供手机网页、账号登录和电脑 WS 隧道。电脑连接配置只有**服务器地址（包含端口）和准入密钥**，账号可绑定多台电脑。

## 安全边界

- 全程使用 `http://` / `ws://`，不使用 HTTPS/WSS，也不是端到端加密。链路观察者和服务器持有者可能读取、篡改账号密码、Cookie、聊天与文件内容。
- 只使用自己控制的服务器，不复用其他网站密码。
- 二维码包含**原始账号、原始密码和本机设备 ID**，可长期重复使用；拿到二维码等同拿到账号密码，不要分享。刷新二维码不撤销旧二维码，修改密码才会让旧码登录失败。
- 本机 `usage-dashboard/relay.json` 持久保存准入密钥、原始账号密码及设备凭据，尽力限制文件权限。普通配置查询不回显密码或密钥；桌面显示二维码时，受保护的本机状态接口会返回含密码的链接。
- 服务端只保存带独立盐的 PBKDF2 密码哈希，以及设备密钥、登录会话的校验值。它不能消除明文传输风险。
- 手机控制可以驱动本机 Agent 读写文件、执行命令。仅用于可信私人环境，不作为面向公众的生产认证服务。

## 一、服务器部署

需要 Linux VPS 和带 `sqlite3` 的 Python 3.8 或更新版本，不安装第三方包。

上传仓库的 `scripts/relay_server.py` 到服务器，例如 `~/kimi-relay/relay_server.py`。此脚本独立部署，不需要复制本机插件的其他 Python 文件。

启动：

```bash
cd ~/kimi-relay
RELAY_TOKEN='<你的准入密钥>' python3 relay_server.py \
  --port 47961 \
  --data-dir "$HOME/.kimi-relay"
```

| 参数 | 含义 |
|---|---|
| `--port` | 唯一监听端口，默认 `47961`；网页、账号接口和 WS 共用 |
| `--data-dir` | 持久化数据目录，默认 `~/.kimi-relay`，保存 `relay.sqlite3` |
| `--token` | 注册/新增设备绑定的准入密钥，也可用 `RELAY_TOKEN` 环境变量提供；必须设置 |

准入密钥须为 1–256 位可见 ASCII 字符，建议使用足够长的随机串。尽量用环境变量，避免密钥出现在进程参数中。脚本只监听 IPv4 `0.0.0.0`；本机连接地址请使用域名或 IPv4。

不再使用 `--tunnel-port`、`--public-port`、`--public-host` 或 `PUBLIC_HOST`。服务端从连接的 Host 获取当前入口，本机严格核对注册回执和配置地址。

### 后台常驻

可用 systemd，例如将脚本放在 `/opt/kimi-relay/relay_server.py`，使用专用的 `kimi-relay` 用户运行：

```ini
[Unit]
Description=Kimi HTTP WS Relay
After=network.target

[Service]
User=kimi-relay
WorkingDirectory=/opt/kimi-relay
EnvironmentFile=/etc/kimi-relay.conf
ExecStart=/usr/bin/python3 /opt/kimi-relay/relay_server.py --port 47961 --data-dir /var/lib/kimi-relay
StateDirectory=kimi-relay
UMask=0077
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

先创建专用用户并确保其有脚本读取权限，再创建仅管理员可读的 `/etc/kimi-relay.conf`：

```text
RELAY_TOKEN=<你的准入密钥>
```

保存服务文件后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now kimi-relay
sudo systemctl status kimi-relay
```

在系统防火墙和云安全组中**只放行所选的一个 TCP 端口**，例如 `47961/tcp`。不再需要另开隧道端口。

## 二、电脑注册账号并绑定

1. 打开桌面侧栏「手机」→「中继服务器」。
2. 服务器地址填写 `http://<服务器IP或域名>:47961`，再填写准入密钥，点击「保存中继配置」。未写协议自动使用 HTTP，未写端口使用 `80`。
3. 填账号、账号密码和电脑名称。账号支持 1–64 位字母、数字或 `_.@-`，区分大小写；密码为 1–128 字符，名称为 1–64 字符。
4. 第一台电脑点击「注册账号并绑定本机」。已有账号则点击「登录账号并绑定本机」。
5. 成功后点击「开启中继连接」。二维码和链接绑定当前保存的账号密码与本机设备 ID。

第二台电脑登录同一个已有账号并绑定，即可加入同一设备列表。自动重连使用独立设备凭据，不需要重复输入密码。账号密码仅在注册/登录绑定时发送，保留原始密码是为了后续生成二维码。

更换服务器地址会清除本机旧账号和设备凭据，并在未提供新准入密钥时清除旧密钥，防止发送到其他服务器；旧服务器上的设备记录不会自动删除。建议换服务器前先解除旧绑定。

## 三、手机使用

### 直接访问服务器

打开 `http://<服务器IP或域名>:47961/`，显示独立于电脑的网页：

1. 输入账号密码，服务器校验后登录。
2. 查看该账号绑定的电脑及在线状态。
3. 选择在线电脑，进入现有 Kimi 聊天与手机面板。

电脑全部离线时，登录页和设备列表依然可用。页面提供刷新设备、退出登录、修改账号密码与解除设备绑定。在聊天页面点开「面板」悬浮球，即可返回「电脑列表」或「退出登录」。

### 扫码直达本机

用手机系统浏览器扫描电脑二维码：登录页从 URL `#fragment` 读取**原始账号密码和目标设备 ID**，清除地址栏凭据信息，再调用与手动登录相同的 `/api/relay/login`。服务端检查账号密码及设备归属后，进入本机；不增加独立扫码凭据或免密登录接口。

即使手机已登录其他账号，也会使用二维码里的账号密码重新登录。目标电脑离线时显示设备列表和提示，不绕过设备归属检查。

## 四、停止、改密码和解绑

| 操作 | 效果 |
|---|---|
| 手机退出登录 | 撤销当前登录会话，关闭其 WebSocket；其他手机不受影响 |
| 修改账号密码 | 注销该账号全部手机登录；旧二维码因密码错误不能再登录 |
| 本机停止连接 | 立即断开本机控制和取消自动恢复，保留设备绑定、账号密码；下次开启可继续使用原二维码 |
| 本机或网页解除设备绑定 | 撤销设备凭据并断开隧道；原二维码不再能进入该设备，但其中账号密码仍可能正常登录账号 |
| 刷新二维码 | 重新显示当前账号密码和设备信息，不撤销旧二维码和已登录手机 |
| 重启服务端或电脑 | 账号、设备和七天手机登录态持久保留；电脑恢复连接后继续使用 |

**修改密码后**，请先在电脑端停止连接，再用同一账号和新密码「登录账号并绑定本机」，更新本机保存密码和二维码。正常情况下复用原设备身份，不增加重复电脑。其他已绑定电脑也须更新各自保存密码，否则它们生成的仍是旧密码二维码。

## 五、升级与数据保留

- 这是新协议，需要**同时更新服务器脚本和本机插件**。旧共享密钥隧道和本机密码配对不自动降级兼容。
- 本机旧 `{host,tunnel_port,public_port,token}` 配置会转换为原公网端口的 HTTP 地址供编辑；服务器需改成单端口部署，然后首次注册/登录绑定。旧本机手机密码不上传、不自动创建服务器账号。
- 手机中继旧登录态失效，需要通过账号登录或新二维码重新登录。局域网和 CF 模式仍保留原本机密码/一次性配对逻辑。
- 更新 Python 后需要按 `HANDOFF.md` 重启本机服务及旧 worker；不要把仅刷新网页当作代码已更新。
- 服务端数据目录须放在代码目录之外。替换脚本、修改端口、重启服务都不要删除 `relay.sqlite3`。备份数据库时先停止服务，恢复时仍使用同一数据库；数据库丢失后无法恢复旧绑定。

## 六、故障排查

| 现象 | 检查 |
|---|---|
| 根地址打不开 | 服务是否运行、唯一端口是否在防火墙及云安全组放行、地址是否包含正确端口 |
| 注册/绑定失败 | 准入密钥、账号密码、服务器版本；同名账号应选择登录，不是重新注册 |
| 设备凭据失效或协议不兼容 | 同时升级两端；从本机停止后重新登录绑定；检查是否另一个进程正在使用同一设备凭据 |
| 手机登录成功但电脑离线 | 本机是否已开启中继、桌面 owner 是否运行、服务器数据库是否被换掉 |
| 改密码后二维码登录失败 | 在每台电脑端用新密码重新登录绑定，再扫描新的二维码 |
| 已在服务器网页解绑，本机还显示绑定 | 先停止连接，再点本机解除绑定清理保存信息，或用原账号重新登录绑定 |
| 绑定成功但本机保存失败 | 检查 `usage-dashboard` 写入权限；到服务器网页解除此次设备记录后重试 |

服务端日志只记录启停和设备连接标识，不记录密码、准入密钥、Cookie、二维码链接或请求正文。
