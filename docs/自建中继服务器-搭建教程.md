# 自建中继服务器 · 搭建教程

> 面向拿到本仓库、想自己部署一台 VPS 当中继的**普通用户**。全程照做即可。
> 文中 `<你的服务器IP>`、`<隧道口>`、`<公网口>`、`<你的密钥>` 都是需要你自己替换的占位符；
> 示例里出现的 `48213` / `47961` 是程序默认值，可以沿用，也可以改成自己的端口。

## ⚠️ 安全警告（先看，别跳）

- **全程明文传输，没有 TLS。** 手机到 VPS 是 `http://`，本机到 VPS 是 `ws://`。
  配对码、登录态 Cookie、聊天会话内容、手机上传的文件，经过 VPS 时**全部是明文**，
  链路上任何能看到流量的人（机房、中间网络、VPS 持有者）都能窃听或篡改。
- **只用你自己控制的 VPS。** 中继服务器上跑的是你的会话流量，VPS 持有者可以看到一切。
  不要用别人的服务器、不要用不明来源的「免费中继」。
- **token 只管准入，不加密内容。** `--token` 的作用只是拦陌生人注册隧道，它不会加密任何传输内容。
- **只用于临时联调和私人测试。** 不要在开着中继连接的手机会话里做敏感操作；
  配对链接和二维码不要发给任何人。
- **建议**：`--token` 必设且密钥够强；不用时及时在面板点「停止」并关掉 VPS 上的进程。

## 一、这是什么 / 什么时候需要它

手机远程连接有三种模式（面板「手机」浮层顶部的三段切换）：

| 模式 | 链路 | 适合场景 |
|---|---|---|
| **内网** | 手机直连电脑局域网 IP | 同一可信 Wi-Fi，最简单 |
| **CF 隧道** | Cloudflare Quick Tunnel（临时随机域名） | 没有 VPS；缺点是地址随机、速度看运气 |
| **中继服务器（本教程）** | 你自己的 VPS 转发 | CF 隧道卡顿或连不上、想要**固定地址**、想自己掌控链路 |

自建中继 = 你在 VPS 上跑一个 Python 转发脚本，本机插件主动连过去建一条隧道，
手机浏览器访问 VPS 的公网地址，请求经 VPS 隧道转发回你电脑。

## 二、你需要准备什么

1. **一台有公网 IP 的 Linux VPS**（Ubuntu / Debian 等均可；`Python ≥ 3.8`，**不需要装任何第三方包**，
   脚本只用标准库）。确认方法：VPS 上执行 `python3 --version`。
2. **两个放行的高位端口**：
   - **隧道口**（默认 `48213`）：本机插件连 VPS 注册隧道用；
   - **公网口**（默认 `47961`）：手机浏览器访问用。
   下文用 `<隧道口>` / `<公网口>` 表示；沿用默认值时直接写 48213 / 47961。
3. **一把共享密钥** `<你的密钥>`：自己生成一把足够强的随机串，例如：

   ```bash
   head -c 24 /dev/urandom | base64
   ```

   这把密钥会在 VPS 启动参数和本机配置里各填一份，两边必须一致。

## 三、第一步：VPS 部署 relay_server.py

### 1. 上传脚本

把仓库里的 `scripts/relay_server.py` 传到 VPS，任选一种方式：

```bash
# 方式 A：本机 scp（在本机终端执行）
scp scripts/relay_server.py <用户名>@<你的服务器IP>:/root/relay_server.py

# 方式 B：VPS 上直接新建文件粘贴
mkdir -p ~/relay && nano ~/relay/relay_server.py   # 粘贴脚本全文保存
```

假设最终脚本放在 `~/relay/relay_server.py`。

### 2. 启动

```bash
cd ~/relay
python3 relay_server.py \
  --tunnel-port <隧道口> \
  --public-port <公网口> \
  --public-host <你的服务器IP>:<公网口> \
  --token <你的密钥>
```

参数逐个说明（与脚本 `main()` 的参数逐字对应）：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--tunnel-port` | 否（默认 48213） | 隧道注册口，本机插件连它。对应本机配置 `tunnel_port` |
| `--public-port` | 否（默认 47961） | 手机公网口，手机浏览器访问它。对应本机配置 `public_port` |
| `--public-host` | **必填** | 填 `<公网IP或域名>:<公网口>`，例如 `relay.example.com:47961`。它会被写进注册回执，决定手机访问地址；**和本机配置 `host` + `public_port` 必须一致**，否则配对校验失败。缺省会直接报错退出（退出码 2） |
| `--token` | 否但**强烈建议** | 注册准入密钥，必须和本机配置 `token` 一致。**不传或传空 = 不校验注册**：任何人扫到你的隧道口都能注册隧道、蹭走你的公网口 |

`--public-host` 也可以用环境变量 `PUBLIC_HOST` 提供，`--token` 可以用 `RELAY_TOKEN` 提供
（适合不想把密钥写进命令行/历史的场景）：

```bash
PUBLIC_HOST=relay.example.com:47961 RELAY_TOKEN=<你的密钥> \
python3 relay_server.py --tunnel-port 48213 --public-port 47961
```

### 3. 后台常驻

**临时跑（nohup）**：

```bash
cd ~/relay
nohup python3 relay_server.py \
  --tunnel-port 48213 --public-port 47961 \
  --public-host <你的服务器IP>:47961 \
  --token <你的密钥> \
  > relay.log 2>&1 &
tail -f relay.log   # 看到 "relay up: tunnel :48213 public :47961" 即监听成功
```

**正式跑（systemd，推荐）**：新建 `/etc/systemd/system/kimi-relay.service`：

```ini
[Unit]
Description=Kimi Usage Panel Relay
After=network.target

[Service]
ExecStart=/usr/bin/python3 /root/relay/relay_server.py --tunnel-port 48213 --public-port 47961 --public-host <你的服务器IP>:47961
Environment=RELAY_TOKEN=<你的密钥>
Restart=always
RestartSec=3
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now kimi-relay
systemctl status kimi-relay        # 应显示 active (running)
journalctl -u kimi-relay -f        # 实时日志
```

> 用 `Environment=RELAY_TOKEN=` 而不是写在 `ExecStart` 里，可以避免密钥出现在 `ps` 输出中。

### 4. 放行端口（两处都要开）

- **VPS 系统防火墙**（按实际防火墙二选一）：

  ```bash
  # ufw
  ufw allow 48213/tcp && ufw allow 47961/tcp
  # firewalld
  firewall-cmd --permanent --add-port=48213/tcp --add-port=47961/tcp && firewall-cmd --reload
  ```

- **云厂商安全组 / 控制台**：阿里云、腾讯云、AWS 等还要在网页控制台的「安全组 / 防火墙」里
  放行这两个 TCP 端口——这一步最容易被忘，系统里开了端口外面照样连不进。

## 四、第二步：本机插件填中继配置

两种方式任选：

**方式 A：面板填写（推荐）**
打开侧栏「手机」浮层 → 模式切到「中继服务器」→ 在配置区填四项 → 点「保存中继配置」：

| 面板字段 | 对应 relay.json 字段 | 填什么 |
|---|---|---|
| 服务器地址 | `host` | `<你的服务器IP>` 或 `relay.example.com`（**只填主机，不带 http:// 和端口**） |
| 隧道端口 | `tunnel_port` | `<隧道口>`，与 VPS `--tunnel-port` 一致（默认 48213） |
| 公网端口 | `public_port` | `<公网口>`，与 VPS `--public-port` 一致（默认 47961） |
| 连接密钥（token） | `token` | `<你的密钥>`，与 VPS `--token` 一致 |

**方式 B：直接编辑配置文件**
编辑 `~/.kimi-code/usage-dashboard/relay.json`（Windows 即 `%USERPROFILE%\.kimi-code\usage-dashboard\relay.json`）：

```json
{
  "host": "<你的服务器IP>",
  "tunnel_port": 48213,
  "public_port": 47961,
  "token": "<你的密钥>"
}
```

注意：

- `host` 不带协议、不带端口；端口走 `public_port` / `tunnel_port` 两个字段。
- `token` 只写不回显：面板/API 只会显示「已设置/未设置」（`token_set`），读不出明文。
- 本机 token 也可以由环境变量 `KIMI_RELAY_TOKEN` 提供；仓库本身不内置任何 token。

## 五、第三步：开启并配对

1. 浮层顶部模式切到「中继服务器」，确认上面四项已保存。
2. 点「开启中继连接」，等状态从「正在开启」变成「已开启」并显示公网地址
   （形如 `http://<你的服务器IP>:<公网口>`）。
3. 隧道就绪且配对码有效后，面板会显示配对链接和二维码。
4. 手机用**系统浏览器**扫码或打开复制的链接（微信等内置浏览器请先切到系统浏览器）。
5. 配对码 10 分钟内有效、成功兑换一台设备即销毁；「生成新二维码」作废旧码签新码，
   不影响已连接的设备。
6. 不用时回浮层点「停止」：吊销全部配对/会话并断开隧道。

## 六、怎么验证部署成功

**VPS 侧：**

```bash
# 两个端口都在 LISTEN
ss -ltnp | grep -E '48213|47961'

# 日志：启动时有 "relay up"，本机连上后每条隧道一条 registered
journalctl -u kimi-relay -f
#   relay up: tunnel :48213  public :47961
#   tunnel registered: <tid>
```

**公网口自检**（VPS 上或任意能访问它的机器）：

```bash
curl -i http://<你的服务器IP>:<公网口>/
```

有隧道在线时返回面板页面/302 之类；没有隧道时返回 `404 unknown tunnel` 或
`404 tunnel not found`——**返回 404 也算服务正常**，说明公网口活着、路由在工作。
连接超时才是端口没放行或进程没起来。

**本机侧：** 面板状态从「正在开启中」变为「已开启」且显示公网地址，
配对链接域名应是你配置的 `host`（而不是别的地址）。

## 七、故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 开启后立即报 `TUNNEL_AUTH_FAILED`「中继密钥错误或未授权」 | ① 本机 token 与 VPS `--token` 不一致；② VPS 设了 token 而本机没填；③ **relay.json `host` 为空/未配置**（v3.4.0 起空 host 也立即报这个码，不再卡「正在开启中」） | 核对两侧密钥逐字一致；确认面板「服务器地址」已填并保存 |
| 卡在「正在开启中」很久后超时（`TUNNEL_TIMEOUT` / `TUNNEL_EXITED`） | 隧道口连不通：端口没放行、VPS 防火墙、云安全组没开、`tunnel_port` 填错、VPS 进程没起来 | `ss -ltnp` 查监听；`curl telnet` 式测隧道口连通性；查安全组 |
| 报错「配对链接校验失败」/ 链接里 host 不对 | VPS `--public-host` 与本机 `host`:`public_port` 不一致（换了服务器没同步改） | 两边改成同一个 host:端口，重启 relay_server 后重新开启 |
| 手机打开报 `tunnel not found` | tid 已失效：本机重新开启换了新隧道，或 VPS 重启/进程重启后墓碑表清空 | 回本机浮层重新开启，重新扫码配对 |
| 手机打开报 `tunnel reconnecting`（503） | worker 掉线正在重连（墓碑期 10 分钟内等它回来） | 稍等几秒刷新；一直不好就回本机停止再开启 |
| 面板里「服务器地址」为空就点了开启 | 同上第一条：`TUNNEL_AUTH_FAILED`，先去填配置 | 填齐四项保存后再开 |
| VPS 日志完全没有 `tunnel registered` | 本机根本没连上隧道口：检查 `tunnel_port`、防火墙、VPS 地址 | 回到「放行端口」逐项查 |
| `curl http://<vps>:<公网口>/` 直接超时 | 公网口没放行 / 进程没跑 | `ss -ltnp`、安全组、进程状态 |

## 八、运维小贴士

- 换 VPS / 换端口：改 VPS 启动参数 + 本机面板四项配置，重新开启即可；`--public-host`
  和本机 `host:public_port` 必须同时换。
- 换密钥：VPS 改 `--token`（或 `RELAY_TOKEN`）重启 + 本机重填 token 保存；旧隧道会断开，
  需重新开启并重新配对。
- 端口建议保留默认高位口（48213/47961），改掉后要同步改三处：VPS 参数、防火墙/安全组、本机配置。
- 长时不用就把 VPS 进程停了（`systemctl stop kimi-relay`），只留配置不跑服务。

## 附：文件与参数速查

| 位置 | 内容 |
|---|---|
| VPS | `relay_server.py`（仓库 `scripts/` 下，单文件纯标准库） |
| VPS 参数 | `--tunnel-port` / `--public-port` / `--public-host`（必填）/ `--token`；env：`PUBLIC_HOST` / `RELAY_TOKEN` |
| 本机配置 | `~/.kimi-code/usage-dashboard/relay.json`：`{host, tunnel_port, public_port, token}` |
| 本机 token env | `KIMI_RELAY_TOKEN`（与 relay.json 二选一） |
| 隧道注册路径 | `ws://<host>:<tunnel_port>/relay/register`（固定，header `X-Relay-Token`） |
| 手机访问路径 | `http://<host>:<public_port>/t/<tunnel_id>/...` |
